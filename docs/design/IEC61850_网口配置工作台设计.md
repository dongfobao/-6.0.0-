# IEC61850 网口配置工作台设计

## 目标

上位机使用两条互不混用的链路：RS485 按 Modbus V10 读取设备实时数据和执行受控写入；以太网负责识别板卡、修改网络参数、上传 IEC61850 模型、验证 TCP 102 和生成总站交付资料。运行模型只使用一个 `.cfg` 文件，Modbus绑定编码在模型DA的 `sAddr` 字段中；将来可保存到板卡 Flash 文件系统，使设备启动不依赖 SD 卡。

当前上位机实现配置项目、固件真实源点选择、统一命名、网络探测和配置包生成校验。配置包生成后即可交付，不提供固件网口下发入口。

## 数据边界

点表只来自 `app/live_register_catalog.py` 的 Modbus V10 定义。首期允许选择固件 `UpdateV10Forwarding` 已实际更新的 39 个源点：

- 4 个模拟量：IR0、IR2、IR4、IR6。
- 30 个状态量：DI0–19、DI34–43。
- 5 个统计量：IR32、IR34、IR44、IR48、IR52。

每个源点生成数值、品质、时间戳三条映射，共 117 条，不超过固件 128 条映射上限。没有进入这份白名单的寄存器不能在界面中伪装成可转发点。

## 上位机工作流

1. 通过 RS485 读取 IR100，必须得到协议字 `0x0A00`，随后读取所选源点并确认数据有效。
2. 输入板卡当前 IP，测试 TCP 102，确认IEC61850服务可达。
3. 设置 IED 名称、逻辑设备名称、统一点名前缀和总站显示名称，选择需要转发的点。
4. 后端检查标识符、IP/掩码/网关、重复对象名、转发白名单和映射容量。
5. 生成设备运行配置、总站点表、ICD 初稿、配置项目和带 SHA-256 的清单。
6. 生成并校验 CFG、映射、ICD、CSV，输出带哈希的配置包。
7. 修改 IP 时设备先返回确认，再延时切换网络；上位机使用新 IP 重新连接 TCP 102。
8. 使用 IEC61850 客户端读取模型和已知点，触发一个状态变化并验证报告，最后保存验收记录。

## 现场命名规则

IEC61850机器对象名和总站中文显示名分别管理。以现场文件 `GUANSHANBIAN_115.icd` 为参考，模拟量对象保持 `AnIn1`、`AnIn2` 等稳定名称，通过每个数据对象的 `desc` 和 `dU` 写入完整中文语义；不同设备或相别由 IED 名称和逻辑设备 `LDevice inst` 区分。

例如总站中文前缀设置为“`三江变电站A相吸湿器`”后：

- `AnIn1` → `三江变电站A相吸湿器上部温度`
- `AnIn2` → `三江变电站A相吸湿器上部湿度`
- `AnIn3` → `三江变电站A相吸湿器压力`
- `AnIn4` → `三江变电站A相吸湿器呼吸流量`

总站实际订阅的是完整对象引用，例如 `SANJIANGBIANLD_Device_A/GGIO1.AnIn1.mag.f`；画面标签从点表或 ICD 的 `desc/dU` 取得。`adfAnIn1` 不在参考现场 ICD 中，不应作为本站模型的对象名照搬。

## 生成文件

| 文件 | 用途 |
|---|---|
| `*_profile.json` | 上位机可再次编辑的配置项目 |
| `*.cfg` | 当前 libiec61850 动态模型输入 |
| `*.cfg` 的 `sAddr` | Modbus V10 源点与模型属性绑定，每点依次为值、品质、时标 |
| `*_point_table.csv` | 总站逐点核对、地址及量纲说明 |
| `*.icd` | 总站工程导入初稿，正式交付前由总站工具校验 |
| `manifest.json` | 文件名、点数、映射数和 SHA-256 |
| `部署说明.txt` | 当前部署能力和操作边界 |

## 验收标准

- RS485 协议字为 `0x0A00`，所选源点能连续读取。
- 配置保存和重新打开后，点选择及命名完全一致。
- 生成包中点数、映射数、引用名称和哈希一致，39 点全选时为 117 条映射。
- TCP 102 可连接，客户端可读取模型并核对点表。
- TCP 102 可连接，客户端可读取 IED/LD/LN/DO/DA 层级。
- 已知模拟量和状态量与同一时刻 Modbus 数据一致；品质与时间戳存在。
- 启用报告后状态变化能主动上送，连续连接和断开不发生设备重启或持续内存下降。
- 取出 SD 卡后重启，活动配置仍可加载；配置损坏时能回退到上一槽。
