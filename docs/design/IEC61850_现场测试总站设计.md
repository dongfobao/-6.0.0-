# IEC 61850 现场测试总站设计

## 1. 建设目标

在“新程序运行数据分析系统”中增加独立的 **IEC 61850 总站**模块，通过电脑网口连接一台或多台吸湿器板卡，供现场调试、联调和交付验收使用。

该模块解决以下问题：

- 导入不同设备的 ICD 文件，建立设备应有的 IEC 61850 模型。
- 在线读取板卡实际模型，并与 ICD 自动比对。
- 按 `IED → LD → LN → DO → DA` 树结构显示实时数据。
- 中文描述、完整 IEC 61850 引用、实时值、单位、品质和时间在同一行对应显示。
- 同时连接多台设备，按变电站、相别和设备名称清楚区分。
- 查看数据集、报告控制块、报告事件、通信诊断和历史趋势。
- 导出现场测试结果，形成总站对接依据。

第一阶段定位为 **现场测试总站和工程调试客户端**。它覆盖当前吸湿器的读取、报告订阅和模型核对需求；遥控、定值写入等可能改变设备状态的功能后续单独开放。

## 2. 与现有“61850配置”模块的关系

两个模块职责不同，但共享一个设备工程：

| 模块 | 用途 | 主要输入 | 主要输出 |
|---|---|---|---|
| 61850配置 | 生成板卡模型和总站交付文件 | Modbus 点表、站名、相别、IP、点名前缀 | 板卡 `.cfg`、总站 `.icd`、点表说明 |
| IEC 61850总站 | 连接板卡并验证模型和实时数据 | ICD、设备 IP、TCP 102 | 实时树、报告事件、模型差异、测试报告 |

配置模块生成工程后，可直接把设备记录和 ICD 交给总站模块，无需再次录入。现场收到第三方 ICD 时，也可以直接导入总站模块作为独立设备。

## 3. 总体架构

浏览器不能直接建立 IEC 61850 使用的原始 TCP 102 连接，因此不能仅靠网页 JavaScript 实现。采用三层结构：

```text
┌──────────────────────────────────────────────────────────────┐
│ 现有网页界面：IEC 61850总站                                  │
│ 多设备总览 / 实时树 / 报告 / SOE / 趋势 / 模型比对 / 诊断    │
└──────────────────────────┬───────────────────────────────────┘
                           │ HTTP命令 + SSE实时推送
┌──────────────────────────▼───────────────────────────────────┐
│ 现有 Python 服务 dashboard_server.py                         │
│ 工程管理 / ICD解析 / SQLite / 事件汇总 / 桥接进程监管         │
└──────────────────────────┬───────────────────────────────────┘
                           │ JSON Lines 标准输入/输出
┌──────────────────────────▼───────────────────────────────────┐
│ iec61850-client-bridge.exe（每台设备一个工作进程）            │
│ libiec61850 客户端：关联、浏览、读取、RCB、报告回调、GI       │
└──────────────────────────┬───────────────────────────────────┘
                           │ MMS / TCP 102
                 ┌─────────▼─────────┐
                 │ 一台或多台板卡     │
                 └───────────────────┘
```

### 3.1 为什么每台设备使用一个桥接进程

- 某台设备连接异常或协议栈出错时，不影响网页服务和其他设备。
- 每个工作进程只串行操作一个 `IedConnection`，避免多线程同时调用连接对象。
- Python 负责重启、超时和状态管理，C/C++ 进程只处理 IEC 61850。
- 比直接用 Python `ctypes` 调 DLL 更容易控制回调生命周期、内存释放和崩溃边界。

项目目录已有 libiec61850 客户端源码和示例，可按当前源码构建桥接程序。现有 `tools/iec61850/iec61850.dll` 的版本、导出接口和许可证来源尚未验证，不作为首选依赖。

### 3.2 数据推送方式

- 网页向后台发送普通 HTTP `POST` 命令。
- 后台通过 SSE 持续推送连接状态、实时值、报告事件和诊断信息。
- SSE 能直接适配现有 `ThreadingHTTPServer`，现场断线后浏览器自动重连，首版不必引入 WebSocket 框架。

## 4. 页面设计

在现有导航中新增 **61850总站**，保留原来的 **61850配置**。

### 4.1 页面总布局

```text
┌─ 工程：三江变电站 ─ 搜索点名/引用 ─ 全部连接 ─ 导入ICD ─ 导出报告 ┐
├───────────────────────────────────────────────────────────────────┤
│ 设备卡1  A相吸湿器 192.168.0.123 ●在线 报告正常 最后数据 10:32:18 │
│ 设备卡2  B相吸湿器 192.168.0.124 ●在线 报告正常 最后数据 10:32:18 │
│ 设备卡3  C相吸湿器 192.168.0.125 ○离线 TCP102超时               │
├───────────────┬──────────────────────────────────┬────────────────┤
│ 多设备模型树   │ 实时点表                         │ 点详情/趋势     │
│ IED            │ 中文描述 | IEC引用 | 值 | 单位   │ 数据类型        │
│ └─LD           │ 品质 | 源时间 | 接收时间 | 来源  │ 品质位解释      │
│   └─GGIO       │                                  │ 所属数据集/RCB  │
│     └─AnIn1    │                                  │ 最近报告        │
│       └─mag.f  │                                  │                 │
└───────────────┴──────────────────────────────────┴────────────────┘
```

示例行必须直接显示：

| 中文描述 | IEC 61850 引用 | 值 | 单位 | 品质 | 数据来源 |
|---|---|---:|---|---|---|
| 三江变电站A相吸湿器上部温度 | `SANJIANGBIANYLDQ/GGIO1.AnIn1.mag.f` | 26.4 | ℃ | good | `urcbAin` 报告 |

这样现场人员既能看懂汉字，也能把同一行的技术引用交给总站工程师配置。

### 4.2 功能页签

1. **设备总览**：所有设备的连接、报告、告警、最后更新时间和数据新鲜度。
2. **实时树**：IEC 层级树与实时点表联动，支持中文和技术引用搜索。
3. **报告与数据集**：查看 DataSet 成员、RCB 参数、启停、GI 和收到的报告。
4. **事件/SOE**：按设备、点、原因和时间过滤，显示值变化和品质变化。
5. **趋势**：选取多个模拟量，显示实时及历史曲线。
6. **模型比对**：ICD 期望模型和在线实际模型的差异。
7. **通信诊断**：网口、TCP 102、MMS 关联、读响应、报告速率和错误码。

### 4.3 状态表达

颜色只作为辅助，所有状态同时显示文字：

- 在线 / 重连中 / 离线 / 配置不匹配。
- `good` / `invalid` / `questionable` 及品质详细位。
- 实时 / 超时 / 旧值。断线后保留最后值，但明确标为“旧值”，不能让现场误认为仍在更新。
- 报告 / 主动读取 / 轮询，明确当前值来源。

## 5. ICD 导入与中文名称规则

### 5.1 首期支持范围

首期完整支持 ICD，后续扩展 CID 和 SCD。导入时解析：

- `IED`、`AccessPoint`、`ConnectedAP` 和 IP 参数。
- `LDevice`、`LN0`、`LN`、`DOI`、`DAI`。
- `DataTypeTemplates` 中的 `LNodeType`、`DOType`、`DAType`、`EnumType`。
- `DataSet/FCDA`。
- `ReportControl` 及其 `TrgOps`、`OptFields`、`RptEnabled`。

导入后保存原始文件、SHA-256、导入时间和解析结果。重新导入同名文件时保留版本记录，避免现场使用错版本。

### 5.2 中文显示名称优先级

每个点同时保存 `technical_ref` 和 `display_name`。中文名称按以下顺序确定：

1. 用户在工程中设置的点别名。
2. `DOI/DAI[@name="dU"]/Val`。
3. `DOI/@desc`。
4. `LNodeType/DO/@desc`。
5. IEC 技术名称，例如 `AnIn1`。

界面允许批量加前缀，例如把“上部温度”显示为“**三江变电站A相吸湿器上部温度**”。前缀只改变工程显示和导出名称，不改变板卡模型中的技术引用，避免总站引用失效。

如果 `dU` 与 `desc` 不一致，模型比对页显示冲突，要求工程人员选择最终显示名；系统不静默覆盖。

## 6. 在线模型发现与模型比对

连接设备后，桥接进程读取实际服务器目录：

1. 获取逻辑设备列表。
2. 获取每个 LD 的逻辑节点和数据对象。
3. 获取变量规格、数据集和 RCB。
4. 生成“在线模型快照”。
5. 与导入 ICD 的期望模型逐项比对。

差异分为：

- ICD 中存在、设备中缺失。
- 设备中存在、ICD 中未定义。
- 数据类型或 FC 不一致。
- DataSet 成员顺序或内容不一致。
- RCB 名称、数据集引用或触发选项不一致。
- IED 名称与所选设备档案不一致。

只有实际匹配的节点才允许订阅或读取。差异结果可导出，作为现场整改清单。

## 7. 实时数据采集流程

### 7.1 连接阶段

```text
TCP 102探测
  → MMS关联
  → 读取服务器标识
  → 在线模型发现
  → ICD模型比对
  → 初始数据快照
  → 配置报告控制块
  → 执行一次GI
  → 进入在线状态
```

每一步都有独立超时和明确错误，不把“端口能连通”当作“61850验证通过”。

### 7.2 数据获取策略

- **报告优先**：对配置到 DataSet 的点启用 URCB，安装报告回调后执行一次 GI。
- **初始快照**：订阅前读取数据集或逐点读取，确保页面首次打开有完整值。
- **轮询补充**：未进入任何报告数据集的点采用可配置轮询，默认 5 秒；限制每台设备的并发请求和每秒请求数。
- **手动读取**：点详情页可执行单点立即读取，并显示 MMS 错误码和耗时。

报告事件至少记录：设备、RCB、序号、报告时间、接收时间、条目引用、值、品质、原因位和完整性标记。

### 7.3 RCB 操作

首期支持：

- 读取 RCB 当前参数。
- 安装和卸载报告处理器。
- 设置 DataSet 引用、`TrgOps` 和 `IntgPd`。
- 启用/禁用 `RptEna`。
- 触发 GI。
- 显示配置版本和报告序号。

当前板卡使用 `urcbAin`、`urcbDin`、`urcbStats`，应作为首个联调样例。BRCB 的 EntryID 续传和缓存报告读取列入后续版本。

## 8. 多设备管理

每台设备保存独立档案：

```json
{
  "id": "sanjiang-a-yldq-01",
  "displayName": "三江变电站A相吸湿器",
  "phase": "A",
  "host": "192.168.0.123",
  "port": 102,
  "expectedIedName": "SANJIANGBIANYLDQ",
  "icdHash": "...",
  "autoConnect": true,
  "pollIntervalMs": 5000
}
```

每台设备拥有独立工作进程、连接状态、重连退避、值缓存和事件队列。所有数据必须携带 `deviceId`，防止多台设备点值串台。

首期以同时连接 16 台设备为设计目标，实际发布前用现场常见电脑验证资源占用。总览页可以按变电站、相别、在线状态和设备类型分组。

### 9.1 桥接进程协议

Python 与桥接进程通过一行一个 JSON 对象通信。

命令示例：

```json
{"id":"c17","cmd":"connect","host":"192.168.0.123","port":102}
{"id":"c18","cmd":"read","ref":"SANJIANGBIANYLDQ/GGIO1.AnIn1.mag.f","fc":"MX"}
{"id":"c19","cmd":"subscribe","rcb":"SANJIANGBIANYLDQ/LLN0.RP.urcbAin01","gi":true}
```

事件示例：

```json
{"event":"connected","deviceId":"sanjiang-a-yldq-01","server":"..."}
{"event":"value","ref":"...AnIn1.mag.f","type":"float","value":26.4,"quality":0,"source":"report"}
{"event":"report","rcb":"urcbAin","seqNum":12,"entries":8,"moreSegments":false}
{"event":"metrics","latencyMs":18,"reportsPerMin":4,"queueDepth":0}
{"event":"error","operation":"read","iedError":10,"message":"object does not exist"}
```

所有协议栈调用由工作进程的单一命令线程执行。报告回调只复制必要数据并入队，不在回调里访问网页、数据库或执行长操作。

## 10. 本地数据存储

使用 Python 自带 SQLite，数据库建议命名为 `iec61850_station.db`，启用 WAL 模式。核心表：

| 表 | 内容 |
|---|---|
| `projects` | 变电站工程及显示设置 |
| `icd_files` | ICD 原文件、版本和哈希 |
| `devices` | IP、端口、相别、IED 名称和连接策略 |
| `model_nodes` | ICD 解析后的树节点和中文名 |
| `datasets` | DataSet 和 FCDA 成员 |
| `report_controls` | RCB 定义和运行状态 |
| `current_values` | 每个设备每个点的最新值 |
| `events` | 报告、值变、品质变、连接事件和错误 |
| `test_runs` | 每次现场测试的起止时间、结果和备注 |

实时值写入采用合并和批量提交，避免高频报告逐条同步写盘。历史保留周期、最大容量和导出后清理策略在设置页配置。

## 11. “总站该有的功能”分级

### 11.1 首期必须完成

- 工程和多设备管理。
- ICD 导入、版本管理和树形解析。
- TCP 102、MMS 关联和设备标识诊断。
- 在线模型浏览与 ICD 自动比对。
- 全数据类型读取，显示值、FC、单位、品质和时间。
- DataSet 查看和读取。
- URCB 查看、启停、GI 和报告解析。
- 多设备实时总览、搜索、过滤和数据新鲜度。
- 事件/SOE、趋势、CSV/JSON 导出。
- 自动生成现场测试报告。
- 断线重连、进程监管和操作审计。

### 11.2 后续增强

- BRCB 缓存报告、EntryID 和断点续传。
- CID/SCD 导入及全站拓扑视图。
- 日志服务、文件服务、定值组服务。
- MMS 写值、直接控制、SBO 控制和控制结果检查。
- IEC 62351/TLS 与证书管理。
- GOOSE/SV 抓包和分析。该功能需要 Npcap，与 MMS 客户端是不同的数据通道。

遥控和写值默认关闭。后续开放时需要设备能力确认、用户角色、二次确认、操作审计和明确的测试模式。当前吸湿器项目先按只读总站交付。

## 12. 可靠性和现场保护

- 后台默认只监听本机地址；需要局域网共享时由用户明确开启并设置访问口令。
- ICD 限制文件大小、XML 深度和节点数，不处理外部实体。
- 每台设备设置有限队列；高频同一点更新可合并，但 SOE 事件不得覆盖。
- 工作进程异常退出后记录退出码并按退避策略重启，连续失败后停止自动重试。
- 连接断开时卸载报告处理器并释放 RCB、MMS 值和连接对象。
- 所有时间同时保存 UTC 和本地显示时间；界面区分设备源时间与电脑接收时间。
- 数据库和导出文件不得阻塞协议回调线程。
- 发布前确认 libiec61850 的许可证使用方式。项目内源码声明 GPLv3，并提供商业授权渠道；闭源现场软件若分发，需要完成许可证选型或采用已授权 SDK。

## 14. 实施顺序

### 阶段 P0：协议桥接可行性验证

先构建最小 `iec61850-client-bridge.exe`，只实现：

1. 连接 `192.168.0.123:102`。
2. 浏览 IED、LD、LN 和数据集。
3. 读取 `AnIn1.mag.f`。
4. 订阅 `urcbAin`，执行 GI 并连续接收报告。
5. 断开、释放并重复连接。

通过条件：读取值与现有 IEC 客户端一致，报告连续 30 分钟，无桥接进程崩溃；连续连接/断开 100 次无资源持续增长。

### 阶段 P1：单设备总站

- 完成 ICD 解析、中文名称解析和在线模型比对。
- 完成实时树、点表、数据集、RCB 和通信诊断页。
- 使用当前三江变电站 ICD 和板卡做端到端验证。

### 阶段 P2：多设备与记录

- 完成设备工作进程监管、SSE 汇总、多设备总览。
- 完成事件/SOE、趋势、数据库和测试报告。
- 验证至少 6 台模拟或实际设备并发，设计能力保持 16 台。

### 阶段 P3：现场发布

- 集成现有 EXE/ZIP 打包流程。
- 检查 Windows 防火墙、网卡选择、静态路由和 TCP 102 占用。
- 完成 24 小时稳定性、断网恢复和错 ICD 测试。
- 输出现场操作说明和总站对接点表。

### 阶段 P4：高级总站能力

按实际合同需要增加 BRCB、控制、定值、SCD、TLS 和 GOOSE/SV，不让这些功能阻塞当前吸湿器的读取和报告验收。

## 15. 验收标准

1. 导入 `GUANSHANBIAN_115.icd` 和三江变电站 ICD 时无解析错误，并能分别建立设备。
2. 页面同一行显示“**三江变电站A相吸湿器上部温度**”、完整 IEC 引用、实时值、单位、品质和时间。
3. 在线模型有缺点、增点、类型差异或 RCB 差异时，界面能准确指出具体引用。
4. 至少 6 台设备同时在线时，数据、报告和事件不串台。
5. 报告订阅、GI、断线重连、浏览器刷新后恢复均正常。
6. 断线后旧值在规定时间内变为“超时/旧值”，不能继续显示为正常实时值。
7. 连续运行 24 小时无后台退出、无数据库无限增长、无明显内存持续上涨。
8. 可导出设备清单、ICD 哈希、模型比对、点值快照、报告状态、错误记录和测试结论。
9. 现场人员只看界面即可把汉字点名与 IEC 61850 树节点逐项对应。

## 16. 首版明确不做的内容

首版不启用遥控、写值、定值修改、GOOSE 发布、SV 采样值和调度自动化。这些功能会改变设备或要求额外网卡抓包能力，应在读取和报告链路稳定后，按现场合同逐项增加。

首个开发目标是让现场人员完成以下闭环：

```text
导入ICD → 添加设备IP → 连接 → 自动比对模型
→ 查看汉字和IEC树对应关系 → 查看实时值和报告
→ 导出现场测试结果
```
